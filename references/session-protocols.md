# 互动课程、状态与复测协议

## 何时读取

开始建档、运行日课、做对话练习、复盘真实材料、更新学习状态或导出 Anki 时读取。

## 总体交互规则

- 一次只要求学习者完成一个清晰动作。
- 等待作答后再展示答案、反馈或下一步。
- 先练后解释；解释只服务于刚出现的任务。
- 保持目标语言的使用量与用户当前理解能力匹配。
- 允许用户随时说“更简单”“更难”“只复习”“解释一下”或切换目标。
- 不用长篇鼓励替代具体反馈，也不因错误中断所有交流。

## 继续学习入口

读取状态后，第一条教学回复直接给一个任务和一个可观察完成条件。优先选择已到期的无答案复测，并根据该行的能力维度、无答案任务和迁移条件生成与它匹配的完成条件；不得套用属于其他重点的“最小完成任务”。没有到期项时才使用 `progress.md` 的“本次唯一重点”和“最小完成任务”。不要先复述档案、列出全部进度、展示模式菜单或预告整课。

如果一个 `recurring` 模式会阻塞当前任务，把它折进同一个任务；只有两个模式在真实情境中确实需要学习者做区分时，才交错最多两个。一次仍只要求一个动作。

## 首次建档状态机

### 入口 A：用户未说语言

第一条回复必须且只能用用户当前的交互语言询问想学习什么语言。中文、英文、日文、韩文和西班牙文分别固定为：`你要学习什么语言？`、`What language do you want to learn?`、`何語を学びたいですか？`、`어떤 언어를 배우고 싶나요?`、`¿Qué idioma quieres aprender?`。其他语言使用自然等义句；无法判断交互语言时才使用中文原句。

### 入口 B：用户已说语言

跳过语言问题。不要直接问用户去该语言对应国家做什么。若听说在目标内，先确认会改变目标声音的必要变体并执行下述“免费声音环境准备”；环境准备完成后再用中性问法确认目标。检查是否存在会改变内容的歧义：

- 变体或地区是否重要？
- 是听说、阅读、写作还是考试目标？
- 用户目标是否已经说明？

只问最重要的一项。不要为了“完整档案”追问所有字段。

### 最小启动信息

获得以下三项即可开始第一课：

1. 目标语言或媒介足够明确。
2. 一个真实目标或默认的基础交流目标。
3. 足以判断零基础或非零基础的信息。

时间、兴趣、设备、多语言情况和习惯字段可以在第一课之间或结束时逐步补齐。首个微任务完成后，如果每日最低任务、固定触发点、可立即打开的材料或低动力备用动作仍为空，一次只补一个字段；用户明确暂不设置时记录为已延后，不反复追问。

### 建立基线

- **完全零基础**：不要考试。听说目标先执行下述“有声输入门槛”，再开始第一个真实功能；纯阅读或写作目标按适配文件处理。
- **接触过但不确定**：给一个短理解选择和一个短产出任务。
- **有实际经验**：用接近目标场景的任务，例如自我介绍并回答追问、读一段短文、写一封短消息或完成服务场景对话。
- **考试目标**：加入代表性题型，但不要只用用户自报分数替代能力样本。

记录基线观察，不急于给 CEFR 或其他等级。只有任务覆盖足够且框架适用时，才给带不确定性的等级映射。

### 有声输入门槛

当目标包含有声语言的听力、口语或发音，且用户能播放声音时：

1. 先完成下述“免费声音环境准备”。在显示新语块的目标语文字、转写、音标、含义或答案前，交付与该语块对应的可播放音频。音频理解题可以先给场景或非文字选项，但不得先泄露目标语文字。
2. 为音源记录类别：`native_official` 表示官方或机构提供的目标变体母语音频，`native_traceable` 表示身份和语境可追溯的母语音频，`tts` 表示合成语音，`not_applicable` 表示任务不需要声音，`pending` 表示尚待取得。依次优先前两类；使用 TTS 时必须在播放器、附件或链接旁直接标注“合成语音（TTS）”。
3. 交付本地音频前，将文件转换为传统 RIFF PCM WAV，并从当前 Skill 安装目录运行 `python3 <skill-dir>/scripts/validate_audio.py <path>`。不要从学习工作区用相对路径寻找脚本。只有退出码为 `0` 时才可交付；成功生成、成功下载、扩展名正确或文件非空都不能代替验证。
4. 外部音频必须确认用户可直接播放目标内容。需要登录、地区不可用、链接失效或只打开文字网页时，不算已交付声音。
5. 验证失败或用户设备无法播放时，不进入模仿步骤，也不记录“已听过”“已跟读”或发音掌握证据。改换兼容格式或音源后重新验证。
6. 暂时无法交付声音时，明确说明限制并暂停听说／发音教学。可提供稍后重试、改用经核实音源，或经用户同意切换为阅读等非声音任务；用户已经明确说只能使用文字并要求继续时，可视为同意文字任务。不得用文字、转写、音标或口型说明冒充声音。

音频技术验证只证明传统 RIFF PCM WAV 结构可解码、时长达到门槛、数据完整并含有效信号；它不证明所有设备都能播放，也不证明发音、变体或语域可靠。仍要单独核实播放器和来源。一个音频包含多个语块时，明确音频与语块的顺序映射。记录来源实际支持的是完整表达、单词、含义、语域还是发音；单词音频不能给完整句发音背书。TTS 只有在目标语言、变体、完整表达文本与用法，以及该 TTS 对该语言变体的支持均已可靠核实时，才可支持明确标注的初步听辨和排练；否则来源保持 `pending`，暂停声音与发音任务，且只有用户同意后才转为文字任务。状态中分别填写表达与语域核实依据、声音文件、目标变体、引擎或说话人、交付方式和技术验证；文件能播放不能替代表达用法核实。TTS 不得单独生成“已模仿母语者”或发音掌握证据。

### 免费声音环境准备

目标语言已知且课程包含听说或发音时，从 Skill 目录运行 `python3 <skill-dir>/scripts/generate_tts.py probe --language <BCP-47> --runtime-dir <workspace-root>/language-learning/.runtime/tts`，按以下免费顺序处理：

1. macOS 优先使用 `say` 和 `afconvert`。缺少目标语言声音时，引导用户在系统设置中下载免费的系统声音后重试。
2. Windows 优先使用 PowerShell `System.Speech.Synthesis.SpeechSynthesizer` 和 Windows 语音包；它不是 Edge TTS。缺少声音时说明将添加的 `Language.TextToSpeech` 能力并取得确认，再调用 `install-windows-voice`。
3. 本地系统声音不可用时，说明联网要求和服务不稳定边界，询问是否允许在工作区隔离虚拟环境中安装免费的 `edge-tts` 与转换依赖；同意后才使用 `--allow-online --install-missing`。不得全局安装。
4. 不要求 API Key、信用卡、付费云 TTS 或订阅。纯阅读、纯写作或明确只用文字的目标可以说明后跳过。

准备完成后，用第一课的一个完整短语运行 `synthesize`，并由内置验证器确认输出 `status: ok`；只有成功后进入有声第一课。

## 规划第一课

从用户目标中选择一个近期可用的微任务，例如：

- 与新认识的人互相介绍。
- 在餐厅询问并点单。
- 请求对方重复和放慢。
- 理解并回复一条工作消息。
- 看懂一条短标题或标识。
- 看懂一条旅行标识并说明下一步动作。
- 用阿拉伯语或日语的目标语域完成一次礼貌请求。

将完成条件写成一个动作，不写成“提高口语”之类抽象目标。

任务的胜利条件至少覆盖核心动作，并根据真实场景加入一个常见追问或沟通修复动作。用户只完成了部分链路时，写“部分完成”，不要把整项任务记为完成。

为起步学习者在 `function-map.md` 中选择与目标最相关的功能，而不是从 F01 机械教到 F30。第一次启用一个功能时，准备学习者自己的版本、常见追问、替换槽位和沟通修复表达；暂时未知时明确保留待建立项。

## 运行一节多轮课程

### 1. 复测旧内容

从到期项目中优先选：

1. 上次未能无提示完成的项目。
2. 会阻塞今日任务的项目。
3. 已隔较久、需要确认保持的项目。

先给场景、意图、音频或视频输入之一，不显示完整答案。根据任务测试理解或产出。

### 2. 提供新输入

每次默认只引入 1–3 个新语块。为每项准备：

- 沟通意图与具体场景。
- 目标语言的自然形式。
- 变体、语域和说话者关系。
- 含义，不依赖逐词对照。
- 起步功能编号；不属于该清单时标记 `not_applicable`。
- 与媒介相符的可靠音频／视频／文本来源；记录来源类别、实际支持内容、可靠性与交付方式，合成内容在播放器旁明确标记。
- 用户自己的真实版本。
- 一个可替换槽位。
- 一个常见回应或追问。
- 一个表达没听懂、没说清或无法完成时可用的修复表达。

先让用户接触输入并猜测主体意义，再补必要说明。对于文字目标或无需声音的媒介，按适配文件更改顺序；有声语言的听说课程不得以暂时缺少母语音频为由绕过上述门槛，使用 TTS 时仍须明确标注并完成技术验证。

### 3. 做感知与模仿

有声音时：

1. 听完整表达，不急着拆字。
2. 辨认一个关键声音、节奏、声调或连接。
3. 分块后还原整句。
4. 学习者自行跟读并再说完整表达；默认不要求上传录音。
5. 用下一轮理解、提取或互动任务继续检验。

不要把上传 MP3 或录音设为课程必需步骤，也不要主动宣传录音百分制。只有宿主明确支持音频输入且用户主动提供时，才评价工具能够可靠观察的少量特征并给定性反馈；文件名、附件占位符、链接或自动转写只能支持相应文本反馈，不能评价音素、重音、节奏、音高或真实可懂度。使用 TTS 作为示范时，不称为母语者对照；需要细致发音确认时转交可追溯母语者、合格教师或可靠语音工具。

不要因工具看不到或听不到就伪造评价。

### 3A. 运行声音—文字基础支线

所有受支持且具有适用正常书写形式的语言都把当前可靠输入连接到目标文字。零基础听说课每课通常只引入一个与当前任务有关的基础单位组，每轮仍只要求一个学习者动作；阅读或写作目标可按表现提高比例。听说目标必须先完成上述声音理解动作，再显示新目标文字；纯阅读、纯写作或无障碍目标按实际媒介直接进入，听说目标缺少音频时只有获得用户同意才进入非声音支线。

1. 从刚理解的完整语块中选择一至五个小型单位，或一个紧凑的拼写—声音、重音、静音、分词、连接或字形规律。
2. 显示正常目标文字；转写只在没有它会阻塞当前动作时提供，并标记为 `full`、`partial`、`none` 或 `accessibility_required`。
3. 立即回到完整语块，并只要求一个辨认位置、声音—字形匹配、分段、拼合、重建或替换动作。
4. 等待学习者回答后，下一轮再在可行时撤去或减少转写重做；`accessibility_required` 不强制淡出。不要用完整字母表、假名表、拼音表或大量字符阻塞当前任务。
5. 在 `progress.md` 保存 `S01+` 基础支线行，关联一个核心字段已填写的现有语块，并把复测任务、`hidden` 答案状态、降低后的转写支架、真实变化条件和后续日期分别写入结构字段。声音相关类型还必须由该语块的完整可靠音源支撑。基础支线行不代表掌握，也不能推进语块、A2 任务或 A2 筛查；只有本轮实际测试的听力、主动口语产出、阅读、写作、互动或发音证据进入 `phrase-bank.md`。

学习者已经熟悉目标语言使用的字母表时，不重教字母名称，改练该语言的实际拼写—声音对应、重音、静音或连读。韩文、假名、阿拉伯文字、汉字等按 [language-adaptation.md](language-adaptation.md) 的单位粒度与结构处理，不强求统一字符数量或固定顺序。

### 4. 做检索与生成

按难度逐步减少支持：

1. 跟随示范。
2. 看意图或场景回忆。
3. 无提示完成原表达。
4. 替换一个槽位。
5. 改变一个语法或语域条件。
6. 在未预告的新情境中使用。

若用户失败，先给最小线索，不要立刻显示整句。记录需要哪一级提示。

需要处理反复错误时，不连续机械重复同一种题。把一个或最多两个 `recurring` 模式放进可理解的变化任务，让学习者根据场景选择、辨别或重新提取；不要使用固定正确率阈值宣布升降级。延迟复测前不得展示工作示例；全新产出可以先短示范，但后续证据任务必须按提示阶梯撤去示范。

### 5. 运行微型互动

说明一个简单胜利条件，然后扮演对话方。不要把每个轮次变成语法测验，也不要把 AI 角色扮演记成真人交流。

允许学习者：

- 请求重复或放慢。
- 确认理解。
- 换一种说法。
- 暂时使用较简单形式完成任务。

互动结束后再集中反馈，除非错误会造成严重误解、冒犯或任务无法继续。把证据类型标为 `simulation`、`real_person` 或 `real_world_task`；只有后两类可以证明真实使用。

### 6. 做语法对答案

只选择一个能解释刚才多个例子的高价值模式：

1. 让用户先观察两三个例子并提出猜测。
2. 给出短规则和一个必要例外。
3. 做一个理解辨别题。
4. 立即要求生成一个新例子。

若用户明确喜欢先看规则、目标是考试、或该语言特征不适合完全后置，则先给微型规则再实践。不要以“忠于方法”为由忽视学习者差异。

### 7. 给反馈并重做

采用“意义 → 模型 → 差异 → 重做 → 迁移”：

- 先说明用户成功表达或理解了什么。
- 给一个自然版本，不罗列所有可能说法。
- 解释最关键的 1–2 个差异。
- 让用户重做同一任务。
- 换一个小情境再试。

把其余非关键错误记录为以后观察项，不在同一轮全部讲完。一次出现只在反复错误队列新增 `observing` 假设，记录真实课次日期、关联语块和下一辨别任务；同一模式累计在至少两个不同真实课次被观察到才改为 `recurring`。观察必须来自工具实际可见或可听的回答媒介：不能从文字或自报创建发音模式，也不能从自报创建任何能力错误结论。下一辨别任务不得包含完整答案。只有无答案变化任务成功后才标为 `resolved`；它只改变队列优先级，不证明模式永久消失，也不自动升级语块、A2 任务或整体等级证据，后续重现时重新激活。

### 8. 结束课程

课程结束时简洁给出：

- 今日完成的真实任务。
- 已能独立完成的内容。
- 仍需何种提示的内容。
- 下次优先复测的 1–3 项。
- 一个与当前能力相配的主动使用动作，轮换独白、情境预演、短日记、兴趣内容和可行的真人／真实场景检查点。
- 已经设置的最低任务和生活触发点；若尚未设置且本课已完成首个微任务，一次只补问其中最关键的一项。

不要用学习时长或鼓励口号代替表现总结。用户只给五分钟时，最多引入一个需要主动使用的核心表达及一个回应／修复表达，达成一个可观察胜利条件后停止；习惯问题留到下一课，除非它替代当前收尾而不增加轮次。

用户已有稳定触发点时，可以提供一次可选微沉浸：把一个当前语块的约 30 秒听辨、提取或观察动作附着到原有行为。只有用户明确同意才将状态改为 `on`，并同时保存触发点和单项动作；拒绝或未询问时保持 `off`。微沉浸不得变成每轮自动插入的额外课程，用户自述完成也不升级能力证据。

## 复测调度

不声称存在唯一最佳算法。遵循：

- 新项目在本课结束前做一次无提示回忆。
- 成功后安排到后续课程，并逐渐拉长间隔。
- 失败后缩短间隔、改变线索或改用另一个情境。
- 在达到 `independent` 后测试变形；达到 `flexible` 后再通过延迟测试进入 `retained`。
- 维护语言优先抽查高价值功能和近期变弱的能力，而不是复习全部材料。

对每个实际测试的能力维度记录日期、任务、提示级别、结果、证据环境、回答媒介、是否迁移和下次复测时间。证据环境使用 `direct_task`、`simulation`、`real_person`、`real_world_task`、`self_report` 或 `not_applicable`；提示级别使用 `model`、`full`、`partial`、`intent`、`none` 或 `not_applicable`；回答媒介使用 `meaning_response`、`target_text`、`romanization`、`audio`、`action`、`self_report` 或 `not_applicable`。尚待用户回答只写在计划或复测队列中，不写成实际证据。`self_report` 不升级能力；口语产出和发音的非 `new` 结果需要可观察音频，发音还要求 `native_official` 或 `native_traceable` 参照；写作的非 `new` 结果需要实际测试正常目标文字，不能用罗马字或把口语答案打出来替代。不要因为同日重复多次成功就直接标记 `retained`，也不要把一个维度的成功复制给其他维度。

证据日期使用实际环境日期，不能因为用户在同一真实日期说“第二天了”而写入未来日期；每条实际证据日期都要对应 `progress.md` 的真实课次标题。`retained` 要求可验证的证据日期严格晚于语块首学日期；时间间隔无法核实时，保留为 `independent`／`flexible` 并把用户自述写在备注。表现记录保存最小、可复核的原答或动作，遮盖与学习证据无关的姓名、地址等个人信息；本地音频用 `file:` 指向已验证 PCM WAV，无法由工作区读取的附件用 `attachment:` 记录并明确其内容未被独立验证。

统一提示级别：`none` 只给开放任务与胜利条件；`intent` 明确给出要表达的完整意思但不显示目标形式；`partial` 给出部分形式或受限细节选项；`full` 让完整答案可见或把完整答案放进选项；`model` 表示刚跟过示范。完整中文句子后的目标语回忆是 `intent`，完整含义三选一是 `full`，12／20 这类受限细节选择至少是 `partial`。

所有目标都维护 `progress.md` 的 A2 任务地图。每项证据要求写成 `P001:listening:core` 这样的 `语块:能力维度:角色`，角色只用 `core`、`follow_up`、`repair`；通过态至少含一个核心要求和一个追问／修复要求，且每个精确要求都达到状态门槛。胜利条件是人读说明，证据要求是机器权威；保存前逐项核对角色、能力和说明一致，不期待验证器理解自由文本。`same_session_passed` 只表示本课独立完成；`changed_condition_passed` 需要变化迁移；`delayed_passed` 需要后续课次无答案保持；`field_checked` 要求全部要求独立完成，并至少有一个无答案 `real_person` 或 `real_world_task` 互动通过。用户自定义域可以参与课程，但不计入通用 A2 内部筛查；任何单项状态都不能直接写成整体 A2。

同时维护 A2 风格内部筛查。只有模板定义的七个通用核心域中至少五个用不同核心语块达到 `delayed_passed` 或 `field_checked`、其中包含 `communication_repair`、六个能力维度都有任务地图精确引用的 `retained` 证据，并且至少一个任务达到 `field_checked` 时，才把状态改为 `evidence_consistent_in_tested_tasks`。筛查摘要分别用 canonical 域名、六个维度枚举和实际 `field_checked` 任务编号，必须与任务地图一致；结论固定为 `证据与已测试任务中的 A2 风格表现一致；正式 CEFR 未确认`。验证器通过后仍要明确未测范围；正式 CEFR 结果必须来自合适的外部测评。

## 状态文件协议

### 读取

持续课程开始前读取：

1. `profile.md`：确认语言、目标和限制是否仍有效。
2. `progress.md`：找出 A2 任务地图、上次唯一重点、到期复测、声音—文字基础支线、反复错误队列和微沉浸状态。
3. `phrase-bank.md`：读取将使用的项目、来源和证据。
4. `function-map.md`：读取高优先级功能、已关联语块和未完成的用户版本／追问／修复项。旧工作区缺少该文件时，从模板补建并只迁移已有证据，不重置课程。

如果文件冲突，以用户最近明确说明为准并做最小更新。不要覆盖用户手写备注。

旧工作区缺少声音—文字基础支线或仍使用 `## 旅行任务地图` 标题时，先从当前 Skill 目录运行 `python3 <skill-dir>/scripts/migrate_workspace.py <workspace-dir>`；迁移器只把旧标题改成 `## A2 任务地图` 并增量插入缺少的当前空表，必须保留全部既有任务行、课次、复测和备注，不把旧旅行域擅自映射为通用核心域。迁移后再运行 workspace 验证器，不从旧课次反推或编造单位、规律或证据。缺少反复错误表或微沉浸字段时，从当前 `progress.md` 模板增量补入；微沉浸默认写 `off`，不得从已有固定触发点推断用户已经同意。若已有真实课次但“本次唯一重点”或“最小完成任务”为空，先从最近课次的“下一步”与到期复测恢复一个彼此匹配的重点和完成条件；无法可靠恢复时只询问会决定下一任务的一项，不虚构旧计划。

档案中的 `目标文字脚本` 使用模板枚举。记录 `target_text` 前检查原答确实包含对应脚本；韩语罗马字、日语罗马字或阿拉伯语转写只能记为 `romanization`。

功能图只关联与学习者角色、沟通方向和实际测试维度相符的证据。听懂对方执行某功能，不能自动证明学习者会主动执行该功能。

### 写入

仅写本课产生的信息：

- 新增或修正的语言档案字段。
- 本课实际接触的语块、来源类别和来源支持范围。
- 用户在各能力维度的实际表现、任务、所需提示和回答媒介；表现记录按媒介写 `response:`、`action:`、`self_report:`、`file:` 或 `attachment:` 可复核前缀。
- 高价值反馈与重做结果。
- 反复错误的观察日期、关联语块、下一辨别任务和状态；一次错误不直接写成 `recurring`。
- 下一次复测和下一课任务。
- A2 任务状态、起步功能覆盖、经用户同意的微沉浸、生活嵌入动作和真实使用证据类型。
- 新接触的声音—文字单位或规律、实质锚定语块、当前与复测转写支架、隐藏答案声明、变化条件和复测日期；不要在基础支线中重复或抬高能力证据。

使用追加或局部编辑。不要为排版美化重写整个文件。

不要从听力理解推断口语产出，从用户说“听完了”推断已经跟读，从朗读推断互动，从 TTS 排练推断母语发音，或从同课成功推断保持。一个回应不足以区分多个动作时，只记录明确部分；如果差异会改变下一步，下一轮只确认最关键的一项。

写入后从 Skill 安装目录运行：

```bash
python3 <skill-dir>/scripts/validate_workspace.py <language-workspace-dir>
```

验证器检查结构和内部一致性，不验证学习证据是否真实。若本次写入导致失败，修正本次写入；不要删除旧证据或用户备注来追求通过。

### 多语言

每种语言使用独立目录。跨语言总览仅在用户要求时创建；不要把不同语言的 phrase ID、来源或证据混在同一文件。

## Anki 可选导出

仅在用户要求时导出。每张卡保留：

- 场景或沟通意图。
- 主动回忆提示。
- 完整目标表达。
- 含义与用户自己的答案。
- 变体／语域。

## 常见请求的行为示例

### “我想学一门语言”

只用用户当前的交互语言回复“你想学习什么语言”的固定或自然等义句；中文回复：“你要学习什么语言？”

### “我想学巴西葡萄牙语”

不要再问语言。若目标未知，问：“你最想先用巴西葡萄牙语完成什么事情？”

### “继续昨天的日语”

读取日语状态，直接给一个到期复测场景；不要先总结整份档案。

### “今天只有五分钟”

切换到最低维护：优先做一个到期复测；需要新内容时最多一个主动核心表达及一个回应／修复表达，完成一个胜利条件后停止，不追加习惯问卷或大块语法。

### “帮我练面试英语”

用具体职位和面试任务建立基线，进行角色扮演和复盘；不要从通用 30 句开始。

### “我想学一种资料很少的语言”

明确说明它超出本 Skill 范围，不继续建课；建议用户寻找该语言社群认可的专门资料、教师或教练，不用模型自行补齐课程。
